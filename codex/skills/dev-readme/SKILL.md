---
name: dev-readme
description: Write or update a project README from verified repository facts when the user requests README work.
---

Write in English. Inspect manifests, entry points, folder structure, tests, CI, and existing documentation before writing. Do not invent features, badges, architecture, installation commands, or roadmap commitments.

Start with a one- or two-sentence project description that can also serve as the GitHub repository description. Include real features, stack, setup and run commands, and tests. Add architecture, API documentation, related projects, license, and author only when applicable and verified.

Prefer short paragraphs and scannable sections; use tables or diagrams when useful and `<details>` for lengthy optional material. Preserve useful existing content. If an essential fact cannot be verified, ask rather than inventing it. Do not change the GitHub repository description unless asked.
